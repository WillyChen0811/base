# pybase.audio：解码、VAD、麦克风轨与会议混音对齐、说话人归属

给"录了一场测试/会议，想知道每段话是谁说的"这类场景用：本机麦克风单录一条
（浏览器开着回声消除，远端声音基本不进），会议软件另录一条混音（本机 + 远端
混成单轨，比如腾讯会议转码的 mp4：h264 + AAC 单声道 32 kHz）。两条轨里本机说的
话都有，远端的话只在混音里有（外放时麦克风会漏一点衰减过的回声）。

依赖 numpy（`pip install "pybase[audio]"`）；`decode_pcm` 另需 ffmpeg 可执行文件。
`import pybase.audio` 本身不加载 numpy，用到哪个名字才加载对应子模块。
定点抽帧在 `pybase.media.frames_at`（只要 ffmpeg，不要 numpy）。

## 用法

```python
from pybase.audio import decode_pcm, speech_segments, align_offset, align_detail, attribute
from pybase.media import frames_at

mic = decode_pcm("record-mic.webm")          # 16 kHz 单声道 float32，经 ffmpeg 管道、不落中间文件
mix = decode_pcm("meeting.mp4")               # 视频文件只取音轨
mic_segs = speech_segments(mic, 16000)        # [(start_ms, end_ms)]，麦克风时间
mix_segs = speech_segments(mix, 16000)        # 混音时间

offset = align_offset(mic, mix, 16000)        # 混音时间 = 麦克风时间 + offset
detail = align_detail(mic, mix, 16000)        # 同上，另带各块的估计（看漂移/中断）

for p in attribute(mic_segs, mix_segs, offset, mic, mix, 16000):
    p   # {"start_ms", "end_ms", "who": "self"|"remote"|"both"|"unknown", "ratio_db"}，混音时间

frames = frames_at("record.webm", [61000, 75250], "analysis/frames")
# [FrameFile(t_ms=61000, path=.../61000.jpg, skipped=None), ...]；抽不到的 path=None、skipped 写原因
```

约定：

- 时间一律整数毫秒；`offset_ms = 混音时间 - 麦克风时间`（麦克风比混音晚开录 1.234 秒 → +1234）。
- 两条 PCM 要同一采样率、单声道（`decode_pcm` 出来的就是）。
- `align_offset` 对不齐（有一条轨整条没起伏、太短、没有能对上的有声块）抛 `AlignError`，不猜一个数。
- `attribute` 的片段拼起来正好覆盖 `mix_segs`；麦克风没覆盖到的混音时段标 `unknown`。
  `ratio_db` 是这片「麦克风/混音」能量比减去本机电平：本机说约 0，远端说约 -回声衰减量。
- 一场会议里录了好几段麦克风（每段 `record-mic.webm` 从 0 起），每段单独对齐；
  段在整场时间轴上的位置（`clips.offset_ms`）和混音时间怎么换算由调用方管。

## 机器分工

- **只在执行设备本机跑**（开着调用方程序的那台，比如 Mac：本机 ffmpeg + numpy）。
- **Ubuntu 不跑**：它的 CPU 不做媒体处理；Ubuntu 发起的活要把解码、抽帧交给 Studio
  （Studio 上的 ffmpeg 接口不在本库）。本库只是函数，不判断自己在哪台机器上。
- 测试：纯逻辑（`tests/test_audio.py`，numpy 合成信号）本机可跑；碰 ffmpeg 的
  （`test_audio_ffmpeg.py`、`test_media_frames.py`）和两小时长轨耗时只在 Studio 跑
  （`py/testenv.json`：conda 装 ffmpeg，设 `PYBASE_LONG_AUDIO_TEST=1`）。

## 算法与阈值怎么定的

阈值都是用 `tests/audio_synth.py` 合成的会议定的（`cd py && python tests/audio_synth.py`
重跑实验）。合成方法：每句话 = 300–3400 Hz 带限噪声 × 音节包络（120–280 ms 的 hann 音节、
音节间 0–60 ms 小空隙、偶有 80–120 ms 停顿）；混音 = 本机 + 远端 + 底噪（-60 dBFS）；麦克风 =
本机（比混音里高 6 dB）+ 远端回声（比混音晚 50 ms，比"按本机电平换算"低 echo dB）+ 底噪（-65 dBFS），
从混音 1.234 秒处开录。一场 43 秒，14 个真值段：本机独白、远端独白、2 秒同时说话、
"远端—本机 0.6 秒短回答—远端"的快速轮换、麦克风没覆盖的开头。

### VAD（`speech_segments`）

30 ms 一帧算 dBFS 能量，阈值缺省 = max(噪声底 + 10 dB, 参考电平 - 40 dB)，但不超过两者中点；
噪声底 = 帧能量第 10 百分位，参考电平 = 第 99 百分位；两者差不到 12 dB 视为整条没人说话，返回 []。
"- 40 dB"那一条是给噪声被降噪压得极低（浏览器、会议软件都会）的轨用的，免得底噪起伏也算话。
过阈值的帧连起来，间隔 < 200 ms 并段，短于 300 ms 丢掉。合成会议（4 个种子，混音和耳机麦克风）上边界误差最大 40 ms。

### 对齐（`align_offset` / `align_detail`）

不做全采样率互相关：5 ms 一帧算包络，粗搜降到 100 ms 一帧，麦克风按 30 秒一块（重叠一半，末尾再放一块）
在整条混音上用 FFT 算皮尔逊相关，相关系数 < 0.2 的块不要；各块的粗搜偏移按 ±100 ms 加权取众数，
和众数相差 ≤ 200 ms 的块再在众数 ±300 ms 内按 5 ms 精搜（抛物线插值），取中位数。
`max_shift_ms` 限定搜索范围，缺省不限（麦克风这段落在混音哪里都能找到）。

两条轨用不同的包络，这是合成实验比出来的（回声晚 50 ms、-20 dB，3 个种子里最差的误差）：

| 麦克风包络 / 混音包络 | 远端与缺省一样响 | 远端响 6 dB | 远端响 10 dB |
|---|---|---|---|
| dB / dB | -11 ms | -18 ms | -24 ms |
| 幅度 / 幅度 | -1 ms | -15 ms，-30/-40 dB 回声时对错几秒或对不上 | -28 ms，同左 |
| **幅度 / dB（采用）** | -1 ms | -8 ms | -13 ms |

麦克风用幅度：回声比本机低 20 dB，幅度只有十分之一，几乎不进相关（用 dB 时回声会把峰往回声延迟方向拽）。
混音用"高出阈值多少 dB"：远端比本机响时，幅度包络会让麦克风里的本机话去对混音里更响的远端话。

耗时（Studio，11/04 实测，`test_align_two_hour_tracks_under_30s`）：两条两小时的 16 kHz 合成轨，对齐 1.0 s（误差 -1 ms，478/479 块同意众数，各块极差 50 ms），两条 VAD 0.1 s，归属 0.2 s；解码不算在内。按录制端/腾讯会议格式编码（webm/opus 48k、m4a/AAC 单声道 32k）再解码，对齐误差 ±1 ms，归属 14/14 段对。

### 归属（`attribute`）

30 ms 一帧，只看混音过阈值的帧：

1. **本机电平**（「麦克风/混音」能量比）自动标定：麦克风有声帧按麦克风功率加权取中位数（本机说话的帧最响，
   占比很小也压得住回声帧）；再去掉比它低 `echo_ratio_db` 以上的帧（回声），每 1 秒按前后 5 秒就地重算，
   跟住会议软件自动增益的慢变化。`self_ratio_db` 给了数就整段用这个数。
2. **本机帧**：在麦克风有声段附近（两头各放宽 120 ms），且 210 ms 窗口平滑后的能量比不比本机电平低
   `echo_ratio_db`（缺省 10 dB）以上。平滑是因为回声比混音晚几十毫秒，逐帧比会乱跳；平滑后稳在"-回声衰减量"。
3. **远端帧**：麦克风没声；或这一帧混音比"本机电平换算"响 4 dB 以上、且不比附近 210 ms 平均电平低 6 dB 以上。
   同时说话时远端填在本机音节的空隙里，所以这条要逐帧看；"不是附近的弱帧"是为了躲开对齐差几毫秒时
   音节起头那几帧的比值乱跳。
4. 两种帧各自隔 < 400 ms 连成片、丢掉短于 150 ms 的；两片重叠处是 both；最后短于 300 ms 的片并进相邻片。

`echo_ratio_db` 缺省 10 dB 的来历——每格是 4 个种子 × 14 段 = 56 段里标对的段数（去掉两头各 200 ms 后
正确覆盖 ≥ 80%），括号里是最差一段的覆盖率：

| 回声 | 对齐最大误差 | 阈值 6 dB | 8 dB | **10 dB** | 12 dB | 14 dB |
|---|---|---|---|---|---|---|
| -10 dB | -12 ms | 54/56 (0.55) | 52/56 (0.18) | 31/56 (0.00) | 30/56 (0.00) | 30/56 (0.00) |
| -14 dB | -6 ms | 56/56 | 56/56 | 56/56 | 54/56 (0.18) | 33/56 (0.00) |
| -17 dB | -3 ms | 56/56 | 56/56 | 56/56 | 56/56 | 56/56 |
| -20 dB（外放） | -2 ms | 56/56 (0.98) | 56/56 | 56/56 | 56/56 | 56/56 |
| -30 dB | 0 ms | 56/56 (0.98) | 56/56 | 56/56 | 56/56 | 56/56 |
| -40 dB（耳机） | +1 ms | 56/56 (0.98) | 56/56 | 56/56 | 56/56 | 56/56 |

阈值小了，同时说话时远端一响（下表第二列），平滑后的能量比就掉到阈值以下，both 被标成 remote；
阈值大了，回声强时（-14 dB）回声被当成本机。10 dB 两头都顾上。换条件后 10 dB 这一列：

| 回声 | 缺省 | 远端响 6 dB（同时说话时比本机响 7.6 dB） | 本机增益慢漂 ±3 dB | 两者都有 |
|---|---|---|---|---|
| -14 dB | 56/56 | 39/56 (0.00) | 50/56 (0.16) | 38/56 (0.00) |
| -17 dB | 56/56 | 52/56 (0.46) | 54/56 (0.60) | 53/56 (0.55) |
| -20 dB | 56/56 | 56/56 | 54/56 (0.60) | 56/56 |
| -40 dB | 56/56 | 56/56 (0.91) | 54/56 (0.60) | 56/56 |

增益漂移那列差的两段都是同时说话的开头晚了几百毫秒（漂移让本机比远端响时，远端被盖住，要等本机音节的空隙才露出来），
多数时长仍标 both。

## 局限

- **外放回声残余**：回声比本机电平低不到约 14 dB（音箱很响、回声消除没压住）时，回声会被当成本机说；
  远端在混音里更响时这个界限退到约 -20 dB。调 `echo_ratio_db` 只是在"压回声"和"认同时说话"之间换。
- **同时说话**：只有远端的声音能从本机音节的空隙里露出来才认得出；一方比另一方响 8 dB 以上，
  或本机连续说没有空隙时，会标成响的那一方。both 的起止误差可到几百毫秒。
- **测试员整场几乎不说话、又是外放**：自动标定会拿回声当本机电平，回声被标成 self。
  这种场次用 `self_ratio_db` 传别的场次标出来的值，或者别用归属结果。
- **麦克风上的非语音**：键盘声、碰麦克风这类声音在麦克风里响、在混音里被会议软件降噪掉，
  远端说话时会被标成 self/both。能量 VAD 分不出话和噪声。
- **时钟漂移 / 录制中断**：只估一个固定偏移。两边时钟有漂移（几小时的轨可能差上百毫秒）、或会议录制中途
  暂停过，`align_detail` 里各块的 `offset_ms` 会随时间变或分成两堆；那样要分段对齐（本库没做），
  按单个偏移归属在后半段会变差。每段麦克风单独对能减轻。
- **测试员在会议里静音**：混音里没有本机的话，麦克风对不上（`AlignError`），或只对上回声。
- `decode_pcm` 不补容器里的时间戳空洞：音频包有断档时 PCM 按包顺序接起来，时间会往前缩。
- `frames_at` 对浏览器 MediaRecorder 录的 webm（不写时长、没有 Cues 索引）：`-ss` 可能要从头解封装
  到那个时间点（不解码，但几小时的文件会慢），每点缺省 30 秒超时；真实长录像上要实测。
