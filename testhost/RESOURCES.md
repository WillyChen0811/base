# Host resource leases (foundation only)

`resources.LeasePool(state_dir, host_id, cpu, memory_gb)` provides file-locked local
admission state and FIFO queues. These values are configured budgets, not detected
machine capacity. There is no daemon, remote dispatch, process launch or process kill.
The client and executor must integrate admission before any workload is started.

One shared local state directory per physical host is mandatory. Separate state
directories do not coordinate with one another; a registry is not a distributed lock.
Studio's macOS supervisor must arbitrate both macOS and VM submissions through this
same instance. Do not run independent copies inside each guest and assume global limits.

```python
pool = LeasePool(state_dir, 'studio', cpu=12, memory_gb=64)
owner = {'pid': supervisor_pid, 'start': verified_start_identity, 'uid': supervisor_uid}
lease = pool.request('run-1', 4, 8, owner)
if lease['state'] == 'running':
    pass  # trusted executor may now launch work
# Once executor has verified all run processes stopped:
pool.release('run-1', owner)
```

For VM budgets, use a host-level `kind='vm'` reservation. Each guest task supplies
`parent=vm_run_id`. Guest usage is bounded by VM capacity but does not add another
host charge. A VM with guest leases cannot be released normally. Nested VMs are
unsupported. Queue order is FIFO inside each resource pool; guest and host queues
do not block unrelated pools. The snapshot includes queue reasons and host usage.

Owner identity must be generated by a trusted executor from process ID, start
identity and UID. Release checks all three to reject an accidentally reused PID.
This is not an authorization boundary against arbitrary code running as the same
OS user; protect the state directory and don't expose scheduler methods directly
to untrusted project tasks.

Recovery uses `pool.recover(probe)`. The quick, bounded trusted probe receives
`run_id, owner, kind` and returns `alive`, `dead` or `unknown`. Only `dead` reclaims
a reservation. Missing or reused supervisor PIDs alone do not establish that
orphaned workloads stopped. The adapter must check the run's process/container
scope too. Probe errors preserve reservations. A VM marked dead must be confirmed
stopped including all guest processes; its guest leases can then be reclaimed.
The resource module never kills a process or matches global process names.

Budget changes are rejected when existing state differs; drain/reconcile before
an explicit administrative state migration. Corrupt state fails closed instead
of silently dropping reservations.
